# FFmpeg GUI —— 常用音视频处理工具箱

一个基于 Python 标准库 tkinter 的 FFmpeg 图形界面，**零第三方依赖**，直接调用系统
环境变量 `PATH` 中的 `ffmpeg` / `ffprobe`，自身不内置任何 FFmpeg 二进制文件。

覆盖日常最常用的 60+ 项音视频操作：格式转换、压缩、剪辑、合并拼接、音频处理、
水印字幕、截图、m3u8 合成与直播流下载、批量处理，同时保留一个可以手写任意参数的自定义命令页。

---

## 一、运行环境

| 项目 | 要求 |
| --- | --- |
| Python | 3.9 及以上，需要自带 `tkinter`（Windows 官方安装包默认包含） |
| FFmpeg | 任意较新版本，`ffmpeg.exe` 与 `ffprobe.exe` 位于 `PATH` 中 |
| 操作系统 | Windows / macOS / Linux |

检查 FFmpeg 是否就绪：

```bash
ffmpeg -version
ffprobe -version
```

如果提示找不到命令，请把 FFmpeg 的 `bin` 目录加入系统环境变量 `PATH`，然后重启程序。
Windows 可直接下载：<https://www.gyan.dev/ffmpeg/builds/>

## 二、启动

```bash
# 方式 1：直接运行
python main.py

# 方式 2：启动时预加载文件（可传多个）
python main.py demo.mp4 logo.png

# 方式 3：双击 run.bat（Windows，自动寻找可用的 Python）
```

程序启动后左上角会显示 `● ffmpeg 已就绪`，鼠标悬停可查看实际使用的 ffmpeg 路径。

## 三、功能一览

### 1. 格式转换
- 视频容器：MP4 / MKV / MOV / WebM / AVI / FLV / TS / WMV / OGV / GIF
- 纯音频格式：MP3 / M4A / AAC / WAV / FLAC / OGG / OPUS / WMA / AC3 / MKA
- 视频编码：H.264 / H.265 / VP9 / AV1 / ProRes / MPEG-4，以及 NVIDIA NVENC、
  Intel QSV、AMD AMF、Apple VideoToolbox 硬件编码（按本机 ffmpeg 实际支持情况自动列出）
- 编码选 `copy` 即「换容器不重编码」，秒级完成且无画质损失
- GIF 使用调色板算法生成，画质远好于默认写法
- 可选：MP4 网络快速播放（+faststart）、保留全部音轨与字幕、保留/清除元数据
- 「保留全部音轨与字幕」会按目标容器逐条调整字幕编码：MP4/MOV 转成 `mov_text`，
  MKV 把不兼容的 `mov_text` 转成 `ass`（其余字幕仍原样复制）

### 2. 压缩 / 画质
- 六种压缩策略：质量优先（CRF 18）/ 均衡（CRF 23）/ 小体积（CRF 28）/
  自定义 CRF / 指定视频码率 / **指定目标体积（MB）**
- 目标体积模式会根据时长与音频码率自动反推视频码率，并加入峰值限制
- 分辨率缩放（4K/2K/1080p/720p/480p/360p/自定义）× 四种缩放方式
  （等比 / 补黑边 / 裁剪填满 / 强制拉伸）
- 帧率限制、编码速度 preset、音频重编码或移除、硬件解码加速

### 3. 剪辑 / 裁剪
- 按起始时间 + 结束时间（或持续时长）截取片段，支持 `00:01:30.5`、`90`、`1.5m` 等写法
- **快速模式**：`-c copy`，不重新编码、瞬间完成（起点对齐到关键帧）
- **精确模式**：重新编码，帧级精确
- 画面裁剪（宽/高/X/Y）、旋转 90°/180°、水平/垂直镜像、任意角度旋转
- **淡入 / 淡出**：分别填写秒数，画面与声音同步过渡（`fade` + `afade`）；
  填写后自动改用精确模式，淡出起点按截取后的片段长度计算

### 4. 合并 / 拼接
五种最常见的合并场景，默认都走「不重新编码」路线：

| 模式 | 说明 |
| --- | --- |
| **首尾拼接** | 把主界面已选的多个视频按列表顺序接成一段 |
| **m3u8 合成** | 把 HLS 播放列表（.m3u8）指向的分片合成一个普通视频文件 |
| **音视频合并** | 画面来自 A、声音来自 B（视频流直接复制，画质无损） |
| **多音轨封装** | 把多个文件的音轨 / 字幕合进同一个 MKV，全部流直接复制 |
| **并排同屏** | 两个视频左右并排或上下堆叠；声音可保留第一路、混合或静音 |

首尾拼接有两种方式：
- **直接拼接（默认）**：只复制视频流与音频流，不重新编码，秒级完成、画质无损。
  要求各文件的分辨率、帧率、编码格式一致。
- **兼容拼接**：重新编码，自动把所有片段统一到同一分辨率、帧率、像素格式、
  采样率与声道，编码不同也能拼。可选择「跟随第一个视频」或指定 1080p / 720p 等。
  还支持**片段间转场**（交叉淡入淡出、擦除、滑动、溶解等 6 种，可设时长）。

「将要处理的文件」框会实时显示拼接顺序，顺序可在主界面用 ↑ ↓ 调整。

#### m3u8 合成与直播流下载（本地列表 / 在线地址）
`.m3u8` 本身只是一份**播放列表**，画面都在分片（`.ts` / `.m4s`）里，
所以这里做的是「列表 + 分片 → 一个可随手播放、可拷贝走的视频文件」。
分片在本地就本地合成，是 http(s) 地址就顺便下载。

**本地列表**
- 把 `.m3u8` 加进主界面文件列表的**第一位**，默认「直接合成」不重新编码，几秒钟完成、画质无损。
- **支持 AES-128 加密的直播回放**：密钥文件（常见 `*.key`）必须和列表、分片放在同一目录。
  ffmpeg 默认不允许列表引用这类扩展名，程序已自动放开。
- 开工前会先读一遍列表，**缺哪个分片 / 密钥就点名哪个**，
  不会让 ffmpeg 丢一句晦涩报错还产出空文件。
- 只有分片、没有列表时（`seg-000.ts` 这类），改用**首尾拼接**。
- 分片之间编码不一致、或要顺便改格式时，用「兼容合成」（重新编码）。

**在线地址与直播录制**（在「在线地址」里填 `http(s)://…/index.m3u8`，填了就优先于本地列表）
- 点播地址直接下载成整片；直播地址会持续跟播，**什么时候结束由你点「停止」决定**。
- 一填在线地址，**输出格式自动切到 mkv**，顶部「输出位置」立刻把真实落点亮出来；
  清空地址会自动还原，你亲手改过的格式不去覆盖它。
- 录制时长（秒）：填了就带 `-t` 到点自停，进度条也按它算百分比；
  留空则不显示百分比（进度条滚动，状态栏显示已用时 / 速度 / 已写入大小），
  因为直播什么时候停是不可预测的，报个百分比反而像卡住。
- **防盗链**：`User-Agent` 与 `Referer` 两个框专门留出来（有「浏览器 UA」一键填）。
  实测服务端不认识 ffmpeg 默认 UA 时会直接 403 拒绝，这两个参数不是摆设；
  它们只随 http(s) 输入下发，本地列表不会带上（带上了 ffmpeg 会报 Option not found）。
- **重连等待**（秒，留空按 30）：断线后的最长退避。实测调大它确实会让 ffmpeg 多等几轮再重试
  （同一个断网窗口，用时从 2.7s 变 5.3s），网络回来后接着录**后面的**内容。
  但要说清楚：**断掉那几秒的分片取不回来**——实测分片取失败时 ffmpeg 直接跳过它继续录，
  最后照样返回成功，产物是一段「中间缺几块」的短片；填了「录制时长」时
  看进度条有没有走满，就能判断有没有缺。
- 输出落在程序目录的 `downloads/`（用地址最后一段命名、自动丢掉 `?签名=…`），
  想改位置就切到「指定输出目录」。
- **边下边播请选 mkv**：实测录制中途，mkv / ts 每写下一段就能打开播放，
  而 mp4 的文件尾（moov）要等写完才存在，中途打开一律 `moov atom not found`，
  所以在线地址的「保持原格式」默认解析成 mkv。
- **点「停止」不会毁掉文件**：程序先向 ffmpeg 送一个 `q` 让它自己写完文件尾
  （实测 mp4 / mkv / ts 都能 rc=0 完整退出），实在不退出才强制结束；
  已录下的部分会保留并在报告里写明「已手动停止 · 已保存 X」，
  只有收尾失败（被强制结束）的半成品才清理掉。

### 5. 音频处理
- 提取音频（10 种输出格式）
- 替换音轨、混音（原声 + 背景音乐，可单独设置背景音乐音量）、
  合并音视频、移除音轨（静音视频）
- 音频滤镜：音量（倍率 / 分贝）、淡入淡出、延迟、高通滤波、
  降噪（`afftdn`）、响度标准化（`loudnorm`，可调目标 LUFS）
- 重采样：采样率、声道数

### 6. 特效 / 叠加
- 变速（快放/慢放，音频自动用 `atempo` 链同步变速且保持音调）
- 文字水印：字号、颜色、位置（九宫格）、边距、不透明度、半透明底衬
  （文本通过临时文件传入，中文与特殊字符不会出错）
- 图片水印 / Logo：按主视频宽度百分比或固定像素缩放
- 画中画：视频叠加视频，可调小窗宽度、位置、边距
- 字幕：烧录硬字幕（`subtitles` 滤镜，支持 srt/ass/ssa/vtt）
  或封装软字幕（MKV 存 srt，MP4 转 mov_text）
- 通用画面调整：亮度、对比度、饱和度、伽马、模糊、锐化（可与任意操作叠加）

### 7. 截图 / 预览
- 单张截图（指定时间点，jpg/png/webp/bmp，可调质量与宽度）
- 批量截图（按间隔抽取，输出 `名称_0001.jpg` 序列）
- 缩略图拼图（列×行 网格总览图）
- 预览动图（导出 GIF 片段）
- 图片序列合成视频（把 `img_%04d.jpg` 这样的序列做成视频）

### 8. 媒体信息
- 完整的 ffprobe 报告：容器、时长、体积、总码率、每个流的编码/分辨率/帧率/
  像素格式/采样率/声道/码率/语言/标题/标记
- 一键复制，或导出为 TXT / JSON

### 9. 自定义命令
- 直接手写 ffmpeg 参数，用 `{input}` 表示源文件、`{output}` 表示输出文件
- 内置 16 个常用参数片段，点击即可插入
- 自动忽略 `-y`、`-hide_banner`、`-progress` 等已由程序统一添加的全局参数
- 支持带引号、带空格的参数（Windows 路径中的反斜杠不会被误解析）

## 四、界面说明

```
┌─ 顶部：程序名 / ffmpeg 状态（悬停查看路径）──────────────┐
├─ 源文件 + 输出位置（可一键「收起 ▲」折成一行，正文可滚动）┤
├─ 功能页（9 个标签页，内容可滚动）──────────────────────┤
├─ 命令行预览（随选项实时更新，可一键复制）───────────────┤
├─ 进度条 + 速度/帧率/输出体积 + 停止/打开输出位置/开始 ───┤
└─ 运行日志（右键可复制 / 全选 / 清空）──────────────────┘
```

- **顶部不再吃掉大半屏**：源文件与输出位置合并成一块，正文高度封顶
  （约 96 × 缩放系数 像素），放不下就出现滚动条 / 滚轮，而不是把中间参数区挤扁。
- **一键收起**：右上角「收起 ▲」把整块折成一行，折叠后头部仍写着
  「源文件 N 个（批量）　→　sample_compressed.mp4」，不用展开也知道要输出成什么。
- **中间那条分隔条可以拖**，默认放在约 56% 处（原来 62%，日志因此只剩两三行），
  命令行预览也压到两行，把高度让给日志。
- **你调过的位置会记住**：窗口尺寸、分隔条停在哪、顶部是否折叠，关窗口时写进
  程序目录的 `settings.json`，下次打开就是上次调好的样子；删掉这个文件就回到默认。
  换过显示器 / 分辨率后旧尺寸会被夹回屏幕范围内，不会出现拖不回来的窗口。
- **批量处理**：在主界面选择多个文件，所有功能页都会逐个文件执行，
  进度条显示整体进度，日志逐个报告成功/失败。
  其中一个文件失败**不会中断整批**，跑完后再汇总「成功 N 个，失败 M 个」，
  失败任务留下的 0 字节文件会被自动清掉。
  （「合并 / 拼接」页是例外：它把已选的多个文件视为一个整体，只输出一个文件。）
- **输出命名**：自动命名会使用 `<原文件名><功能后缀>.<扩展名>`，
  例如 `旅行_compressed.mp4`、`旅行_audio.mp3`。
- **执行前会二次确认**：输出路径与源文件相同、多个任务写入同一文件、
  输出文件被其他程序占用等情况都会提前拦截并提示。
  勾选「覆盖」时只做写入探测，不会先把同名文件删掉——任务中途失败也还在。

## 五、高 DPI / 缩放

程序在创建窗口**之前**就声明了 DPI 感知，因此：

- Windows 显示缩放为 125% / 150% 时，界面不会被系统拉伸模糊；
- 字号会按实际 DPI 自动放大，控件尺寸同步调整；
- 窗口初始尺寸自适应屏幕，小屏（如 1366×768）上会自动收缩并允许拖动中间分隔条；
  上一次调好的尺寸 / 分隔条位置会从 `settings.json` 还原，并按当前屏幕夹回范围内。

如需手动指定缩放系数，可设置环境变量 `FFGUI_SCALE`（默认自动检测）：

```bat
set FFGUI_SCALE=1.25
python main.py
```

## 七、进度显示

进度条按 **ffmpeg 实际处理的帧数** 计算，而不是按时间估算：

```
[████████████░░░░░░░░]  62.4%
帧 1874/3000  ·  已用时 00:00:12  ·  速度 2.4x  ·  187 fps
```

**总帧数是怎么确定的**（依次尝试，前一步拿不到才走下一下）：

1. ffprobe 的 `nb_frames` —— 最精确，MP4 / MOV / AVI 等通常都有；
2. ffprobe `-count_packets` 统计的包数 —— 用于 H.264/HEVC **裸流**、部分 TS/FLV、
   单张图片等既不写 `nb_frames` 也读不到时长的媒体（只读包头、不解码，毫秒级）；
3. 时长 × 帧率估算 —— 兜底方案。

**各功能页会按实际输出规模预估帧数**，而不是一律沿用源文件帧数：

| 操作 | 输出帧数 |
| --- | --- |
| 剪辑 / 裁剪 | 截取时长 × 源帧率 |
| 限制帧率 | 输出时长 × 目标帧率 |
| 变速 | 源帧数 ÷ 倍率 |
| 拼接 / 转场 | 各段之和（转场再按时长折减） |
| 提取音频、单张截图 | 按实际输出（无视频帧则退回按时间推进） |
| m3u8 下载（填了录制时长） | 录制时长 × 帧率，百分比准确 |
| 直播录制（未填录制时长） | 无法预知终点：进度条走滚动动画，状态栏显示「已用时 · 速度 · 已写入大小」，看到数字在涨就知道还在录 |

**三重保险**，确保进度条不会卡住或倒退：

- **帧数 / 时间双口径取较大值** —— 避免剪辑、改帧率等「输出帧数少于源帧数」的
  场景算出偏小的百分比（例如 4 秒片段被算成 20%）后停住；
- **`progress=end` 直接置 100%** —— 不会在最后几帧停住；
- **进度只进不退** —— 某项指标抖动不会让进度条回跳。

当总帧数与时长都拿不到时（如探测失败），进度条会退化为滚动动画并显示「处理中」，
而不是冻在 0%，看起来像卡死。

> **文件名含中文 / 特殊符号不会有影响。** ffprobe 输出的是 UTF-8，而 Windows 中文
> 环境默认编码为 GBK；程序已对所有子进程显式指定 `encoding="utf-8"`，因此
> `中文名称.mp4`、`《书名号》.mp4`、含 emoji 的文件名都能正确解析出时长与帧数。

## 八、关于临时文件

程序**不会**往系统盘的临时目录（`C:\Users\...\AppData\Local\Temp`）写任何东西，
所有临时文件都放在：

```
<程序目录>/temp/
```

需要落地的临时文件只有两类，都是 ffmpeg 强制要求从文件读取的输入：

| 文件 | 来源 | 说明 |
| --- | --- | --- |
| `concat_<输出文件名>.txt` | 「合并 / 拼接」直接拼接 | ffmpeg 的 concat 分离器必须从文件读取片段清单 |
| `watermark_<进程号>_<行号>.txt` | 「特效」文字水印 | drawtext 用 `textfile` 读取文本，可完全绕开转义问题 |

生命周期：

- 文件名确定，不会每次刷新预览都变化；
- 任务结束（成功 / 失败 / 取消）后立即删除；
- 程序关闭时清空 `temp/` 目录；
- 下次启动还会清理超过 12 小时的历史残留；
- 这个文件夹可以随时整个删掉，程序会自动重建。

如果程序目录不可写（例如装在 `Program Files` 下），会自动改用
`<系统临时目录>/ffmpeg-gui/`。其余所有功能都不产生任何临时文件。

## 八b、运行日志（排查问题就靠它）

界面上「日志」区看到的每一行，都会**同时实时追加**到：

```
<程序目录>/log/run-年月日-时分秒.log
```

- **逐行落盘、当场 flush**：不等界面那 120ms 的批量刷新。界面卡住、进程被掐掉，
  日志仍然完整——出事当场的最后几行恰恰是最有用的。
- **一次运行一个文件**，只追加不覆盖，方便对比「上一次还能跑」和「这次不行」；
  超过 **30 天**的旧日志在下次启动时自动回收（只认 `run-*.log`，不会碰你放进去的别的文件）。
- 文件开头会记录环境信息：启动时间、Python 版本与系统、命令行、
  ffmpeg / ffprobe 路径与版本——报障时最常被追问的几项都在这里。
- 记录了每次执行的**完整命令行**和 ffmpeg 的原话（错误、警告都按原样写入）。
- **在线地址的签名参数自动脱敏**：`…m3u8?sign=xxx&token=yyy` 落盘时写成
  `…m3u8?<参数已隐藏>`。日志经常要被贴到群里求助，签名跟着走等于把链接送给别人。
- 未捕获异常（包括后台线程里的）也会记进来：用 `pythonw.exe` / 「发送到」启动时
  根本没有控制台，没有这条日志就什么线索都不剩。同时原来的 traceback 仍会照常
  打到控制台，接管只是为了多存一份。
- 界面启动时的第一屏日志里就写着本次日志文件的完整路径，右键日志区也能全选复制。

## 九、常见问题

**Q：提示「未找到 ffmpeg」？**
A：把 ffmpeg 的 `bin` 目录加入 `PATH` 后重启程序。程序也会尝试在
`C:\ffmpeg\bin`、`D:\ProgramFiles\ffmpeg\...` 等常见位置自动搜索。

**Q：日志里出现红色错误但任务显示成功？**
A：ffmpeg 的许多提示包含 "error" 字样但属于可忽略的警告，
最终以退出码与输出文件是否生成为准。

**Q：硬件编码（NVENC/QSV/AMF）不可用？**
A：下拉框中只会列出本机 ffmpeg 实际编译支持的编码器；
即使列出，也需要对应的显卡与驱动。建议先用软件编码 `libx264` 验证流程。

**Q：日志提示「无法确定输出规模，进度条将以『处理中』动画显示」？**
A：说明这个文件既读不到总帧数也读不到时长。常见于：极少数特殊封装、
文件损坏或仍在被其他程序写入。正常视频（含中文名、裸流、单张图片）都不会出现，
程序会依次用 `nb_frames` → `-count_packets` → 时长×帧率 三重方式推算。
此时任务仍会正常执行，只是无法显示精确百分比。

**Q：进度条百分比和「帧 N/M」的含义？**
A：`M` 是本功能页按实际输出规模预估的总帧数（见「七、进度显示」），
`N` 是 ffmpeg 已处理的帧数。因此剪辑后的片段会从 `帧 1/240` 开始，
而不是按源视频的总帧数计算。

**Q：如何确认各功能真正可用？**
A：运行 `python selftest.py`，它会自动生成测试素材，逐个功能页实际执行并校验输出。
目前共 180 项断言，覆盖各功能页真实执行、进度计算、布局重叠、
文件名编码与无元数据媒体的探测兜底、字幕流按容器换编码、
批量任务失败后继续执行、缩放是否保持宽高比、m3u8（含 AES-128 加密分片）合成、
在线 m3u8 下载（本地起 http 服务，验证防盗链 UA 真的决定 403/200、分片请求带头、
`-t` 录制时长）、边下边播（mkv 可开、mp4 缺 moov 打不开）、
点「停止」后优雅收尾并保留已录内容、运行日志实时落盘与签名脱敏、填地址后自动选 mkv 与落点回显、重连参数下发、顶部高度封顶/折叠与偏好记忆等回归点。

约定两条：测试素材与所有中间文件只写程序目录的 `temp/`（不碰系统盘临时目录），
跑完自动删除；界面一律用离屏几何测量校验，**不做窗口截图比对**——
截图取到的是当时最前台的窗口，既不稳定也无法无人值守。
